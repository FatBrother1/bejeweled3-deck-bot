# 内存读取后端

直接读游戏进程里的 Board / Piece 对象拿棋盘，不走图像识别。

这个后端是**站在别人肩膀上**做的：完整的对象布局来自一个公开的逆向项目，
我只是把它验证、移植到 Linux/Proton 环境，并做成了 bot 能用的形式。

这个项目的 README 明确写着"仅在 Steam 版本的 Bejeweled 3 上经过测试"，
它用 `ReadProcessMemory` 读写游戏内存，提供了数据显示、局面保存/读取等功能。

**本项目用的全部地址常量都来自这个仓库的 `main.py`**，主要是这个函数：

```python
def readGem(x, y):
    gem = {
        "address": read4Bytes(0x008E1730, [0xBE8, 0xF8 + 4 * x + 32 * y]),
        "color":   read4Bytes(0x008E1730, [0xBE8, 0xF8 + 4 * x + 32 * y, 0x220]),
        "special": read4Bytes(0x008E1730, [0xBE8, 0xF8 + 4 * x + 32 * y, 0x228]),
    }
    if gem["special"] == 2:
        gem["preColor"] = read4Bytes(0x008E1730, [0xBE8, 0xF8 + 4 * x + 32 * y, 0x21C])
    return gem
```

以及状态与分数的读取：


### 结构性参考：bognarit80/Bejeweled3PlusExtender

| 项 | 内容 |
|---|---|
| 仓库 | https://github.com/bognarit80/Bejeweled3PlusExtender |
| 语言 | C++ |
| 目标 | `Bejeweled3Plus.exe`（**改造版，非 Steam 原版**）|

这个项目针对的是被改造过的 `Bejeweled3Plus.exe`，**它的地址偏移在 Steam 版上不能用**
（`gApp` 槽不一样、Board 偏移差 4 字节）。但它给出了**对象模型**：

- 棋盘是对象图，不是一个 64 长的颜色数组
- `Board` 对象里有分数、关卡、背景等字段
- 每颗宝石是独立的 `Piece` 对象
- 颜色和状态位**分存在两个字段**

有了这个模型，才知道去找"一个指向 Board 的全局槽"，而不是盲扫 1.1 GB 内存找数组形状。

它的 `gamefunctions.cpp` 里这些函数签名也直接说明了字段语义：

```cpp
int  GetScore(uintptr_t theBoard) { return *(int*)(theBoard + 0xD28); }
int  GetLevel(uintptr_t theBoard) { return *(int*)(theBoard + 0xE0C) + 1; }
int  GetGemColor(uintptr_t gemPtr) { return *(int*)(gemPtr + 544); }   // 0x220
int  GetGemFlags(uintptr_t gemPtr) { return *(int*)(gemPtr + 552); }   // 0x228
```

### 颜色 / 状态位枚举

两边一致，互相印证：

```
PieceColor:  -1=未着色  0=红  1=白  2=绿  3=黄  4=紫  5=橙  6=蓝
PieceFlag:   1=火焰  2=超立方体  4=闪电  5=超新星  16=倍率  32=步数炸弹
             64=时间炸弹  128=蝴蝶  256=毁灭  512=计数器  1024=硬币  16384=骷髅
```

## 我在原基础上做了什么

原项目是 **Windows 版**（`ctypes.windll` + `ReadProcessMemory`），我这里跑的是
**Linux + Proton**。所以有这些改动：

**① 换掉读取方式。** 用 `process_vm_readv`（Linux 系统调用）替代
`ReadProcessMemory`，同 uid 不需要 root，也不需要注入。

**② 接进 bot 的接口。** 原项目是个带界面的独立工具；这里做成了
`MemReader` 类，和原来的 `FastReader` 同接口（`wait_still_and_read` /
`read_now` / `fingerprint`），bot 那边只要换一行。

**③ 验证。** 原项目的偏移没人验证过是否适用于 Proton 环境。我做了实机验证，
结论是**完全适用**（见下）。

**④ 解决超立方体误判。** 超立方体没有固定颜色（`color = -1`），但状态位是 2。
只看颜色会把它当成未知格，导致求解器误判死局。

**⑤ 混合静止判定。** 这是最重要的一条，见下节。

### 分数链确认

画面分数 850 时：

```
[Board + 0xD24] = 850    ← Steam 版位置，对
[Board + 0xD28] = 0      ← Plus 版位置，是 0
```

**所以 Steam 版要用 `+0xD24`，不是 Plus 版的 `+0xD28`。**

顺带发现：原来 bot 用的三个**绝对地址已经失效**了 ——

```
0x0A1DE408 = 504650        停在旧值不动
0x2A542394 = -1104802816   垃圾
0x2A5423D4 = 711177448     垃圾
```

而 Board 链一直是对的。所以现在 `score()` 优先走 Board 链。

对比视觉识别的 54~77 ms/步，快约 50 倍。

## 混合静止判定（重要）

**这一条是踩了坑才明白的，也是最终方案的关键。**

### 先说纯内存为什么不行

一开始我以为内存一切都比视觉好，就完全用内存的"数据稳定性"来判断画面静止。
结果有效率掉到 **90%**（视觉是 99%）。

日志里的症状：

```
#12  (0,2)<->(1,2) 实际=0    ✗拉黑
#13  (0,2)<->(1,2) 实际=100  ✓      ← 同一个走法，重试就成功
```

同一个走法，前一次被拒绝、紧接着重试就成功 —— 典型的"出手太早"。

**根因**：过场 / 换关动画实测约 **8.45 秒**。这段时间里，
**内存中的棋盘数据是完全冻结的** —— 每 5ms 读一次都稳定不变，
于是被误判成"画面静止、可以出手"，可游戏其实在播动画，交换必然被拒。

视觉路线因为**看得见画面在动**，天然会等。这是它唯一的、但也是决定性的优势。

### 最终方案

**静止判定交给像素差，棋盘数据交给内存。**

```python
# 用抓帧算像素差，等到画面真的不动了……
a, d = self._pix_diff()
if d < thr: q += 1
# ……这时候才从内存读棋盘
g, bad, _ = self._read_grid()
```

抓帧只用来判"动画演完没有"，棋盘数据完全不经过视觉，所以
火焰宝石读成白色、超立方体误判、标定依赖关卡背景这些问题一个都不存在。

### 效果

| 后端 | 有效率 | 分/秒 | 识别耗时 |
|---|---|---|---|
| 纯内存 | 90% | 97.4 | 0 ms |
| 纯视觉 | 99% | 110.7 | 76 ms |
| **混合** | **98% / 94%** | **144.5 / 136.0** | **0 ms** |

混合两轮的分/秒是三者里最高的。

## 已知限制

**① 偏移依赖游戏版本。** 这组地址是针对 `Bejeweled3.exe`
（5,484,400 字节，2019-07-14）验证的。**游戏一更新，偏移大概率失效。**
所以 `--vision auto` 会先检查可用性，不可用就自动退回视觉后端。

**② 只充分验证了禅意模式。** 经典、闪电、牌局、冰风暴这些模式的
Board 对象布局可能不同（不同模式对应不同的 BoardType）。**尚未逐个测过。**

**③ 超立方体的颜色是 -1。** 已按状态位处理（当作 `S`），
但如果出现"既无颜色又无状态位"的宝石，仍会算未知格。

**④ 混合模式需要标定。** 像素差判静止依赖 `board.json` 里的棋盘区域；
标定不对会影响静止判定（但读棋盘仍然正确，因为走内存）。

## 安全性

**只读。** 仅使用 `process_vm_readv`，具体来说：

- 不写内存（原项目里的 `write4Bytes` 没有引入）
- 不调用游戏内部函数（`IsBoardStill` 那种需要注入的没用）
- 不用 root、不用 sudo
- 不修改任何游戏文件

读的内容就是棋盘上摆着什么颜色的宝石，和一个玩家看屏幕得到的信息一样。

## 怎么用

```bash
# 自动选择（默认）：内存可用就用内存，失效自动退视觉
python3 bot_v6.py

# 强制内存
python3 bot_v6.py --vision mem

# 强制视觉
python3 bot_v6.py --vision vision_np

# 自检：读一次棋盘并打印
python3 reader_mem.py
```

`reader_mem.py` 直接运行会打印当前棋盘、分数、关卡和特殊宝石列表，
可以拿来快速确认环境是否正常。
