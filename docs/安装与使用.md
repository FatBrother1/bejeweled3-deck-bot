# 安装与使用

## Steam Deck

先装依赖：

```bash
sudo pacman -S --needed python-numpy python-evdev python-pillow \
    gstreamer gst-plugin-pipewire xdotool
```

Debian 或 Ubuntu：

```bash
sudo apt install python3-numpy python3-evdev python3-pil \
    gstreamer1.0-tools gstreamer1.0-pipewire xdotool
```

然后装 bot：

```bash
git clone https://github.com/FatBrother1/bejeweled3-deck-bot.git
cd bejeweled3-deck-bot/bot
bash install.sh
```

安装脚本会检查依赖、把脚本里的路径改成你的实际目录、建 `bjbot/` 目录存标定和
日志，最后做个自检。想装到别的地方就 `bash install.sh /home/deck`。

## 标定

这一步不能跳。跑：

```bash
python3 calib.py
```

它会存一张 `calib_overlay.png`。打开看，紫色小圆点应该落在每颗宝石的正中心，
青色方框应该正好框住整个棋盘。

同时它会打印识别结果，未知格必须是 0。

看着对了就写进去：

```bash
python3 calib.py --x0 476 --y0 79 --px 89.17 --py 88.17 --save
```

没做成全自动是有原因的。覆盖率这个指标会随关卡背景变，同一套正确参数白天
丛林是 0.912，夜间森林只有 0.568，自动搜索在夜间会漂到错位置还以为自己找对了。
所以最后得人眼看一眼。

## 日常使用

`run2.sh` 就是控制台：

```bash
./run2.sh on        # 开，守护模式
./run2.sh off       # 关
./run2.sh status    # 看状态
./run2.sh logs 50   # 看日志
./run2.sh play 20   # 手动跑 20 步
./run2.sh dry 3     # 只识别不点击
```

`on` 之后游戏一启动它就跟着跑，游戏退了它就停。重启 Deck 之后没了，
不会开机自启。

想确认环境行不行：

```bash
./run2.sh dry 3
```

未知格是 0 就没问题。

## 游戏模式开关

游戏模式没有终端，所以做成 Decky 插件。前提是已经装了 Decky Loader。

构建：

```bash
cd decky-plugin/BJBot
npm install
npm run build
node verify.mjs
```

注意 `npm install` 在 arm64 机器上要把 `@rollup/rollup-linux-x64-gnu` 换成
`arm64-gnu`，否则报 EBADPLATFORM。

安装：

```bash
sudo cp -r . /home/deck/homebrew/plugins/BJBot
sudo chown -R deck:deck /home/deck/homebrew/plugins/BJBot
sudo systemctl restart plugin_loader
```

重启之后等半分钟，游戏模式里按侧边栏，能找到 BJBot。

出问题就回滚：

```bash
bash rollback.sh
```

## 别的 Linux 机器

不是只有 Steam Deck 能装，但有几个条件：

游戏得跑在 Linux 上，原生或者 Proton 都行，因为方案是纯视觉的，不关心游戏
怎么跑。得有 PipeWire，抓屏靠它，这个是最主要的门槛。python3 加上 numpy、
evdev、Pillow。gstreamer 加 gst-plugin-pipewire。`/dev/uinput` 可写，用来模拟
鼠标。xdotool 可选，只在关弹窗的时候用。

换机器要改两个地方。

第一是棋盘标定，分辨率不一样位置就不一样：

```bash
python3 calib.py
```

第二是 PipeWire 节点号。`capture_pw.py` 里的 `path=93` 是本机的节点号，
换机器基本都要改：

```bash
pw-cli ls Node | grep -A2 "node.name"
```

找到游戏的视频流，把 `path=93` 换成新的编号。

没装 PipeWire 的纯 X11 环境得把抓屏实现改掉，那部分我没写也没试过。

## 高清补丁

不是必须装，但换了画质就得重新标定。

`vision_np.py` 里的颜色阈值是按 1280x800 加汉化高清补丁实测调的。

同分辨率加高清补丁，直接用。同分辨率但用原版素材，可能要调颜色阈值。
其他分辨率得跑 `calib.py --save` 再验证识别。其他语言版本一般也行，
因为识别不看文字，但菜单按钮位置可能不一样。

判断办法还是那个：

```bash
./run2.sh dry 3
```

未知格是 0 就没问题。

## 出问题的时候

抓帧失败一般是 PipeWire 节点号变了，或者 `XDG_RUNTIME_DIR` 没设。

分数不涨、反复走同一招，基本是标定没对准，跑 `calib.py` 看那张 overlay 图。

bot 不动，先 `./run2.sh status` 看三个状态，再看 `./run2.sh logs`。

卡在弹窗上，内置的抗遮挡会自己试着关，不行就手动按 ESC。

换关卡之后失效，可能是新关卡背景变化太大，重新 `calib.py` 确认一下。

想让它跑更快就别调了，已经贴着物理上限，再快就是丢步。

插件面板空白，先看 `node verify.mjs` 是不是全过，不行就 `rollback.sh`。

几个已知的限制：别用 sudo 跑 bot，会把 `XDG_RUNTIME_DIR` 清掉导致 PipeWire
失败。`pkill -f` 在 SSH 里如果模式匹配到自己的命令行会把进程杀掉，用 `[x]`
转义。绝对定位的虚拟鼠标不生效，必须用 `vmouse2.py` 那套相对移动。

## 参数

`bot/bot_v6.py`：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--engine` | pro | pro 或者 fast，推荐 pro |
| `--still-ms` | 250 | 静止窗，实测这个值最好，不建议改 |
| `--vision` | vision_np | 识别后端 |
| `--moves` | 0 | 跑多少步，0 是一直跑 |
| `--out` | — | 结果存哪 |

---

遇到问题的话，把 `./run2.sh status` 和 `./run2.sh logs 30` 的输出带上。
