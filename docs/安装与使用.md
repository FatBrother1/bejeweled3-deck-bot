# 安装与使用

## 一、Steam Deck（推荐）

### 1. 装依赖

```bash
sudo pacman -S --needed python-numpy python-evdev python-pillow \
    gstreamer gst-plugin-pipewire xdotool
```

### 2. 装 bot

```bash
git clone https://github.com/<你的用户名>/bejeweled3-deck-bot.git
cd bejeweled3-deck-bot/bot
bash install.sh              # 装到 $HOME
# 或指定目录： bash install.sh /home/deck
```

安装脚本会：
- 检查依赖
- 把脚本里的 `/home/deck` 自动替换成你的实际目录
- 建 `bjbot/` 目录（存标定和日志）
- 语法 + 标定自检

### 3. 标定（重要）

```bash
python3 calib.py             # 看当前标定准不准
```

它会生成 `calib_overlay.png`：
- **紫色小圆点应落在每颗宝石正中心**
- **青色方框应正好框住整个棋盘**

同时打印识别结果 —— **未知格必须是 0**。确认对准后：

```bash
python3 calib.py --x0 <x> --y0 <y> --px <px> --py <py> --save
```

> ⚠️ **标定不能全自动**：覆盖率指标随关卡背景变化
> （同一套正确参数：白天丛林 0.912 / 夜间森林 0.568），
> 自动搜索会漂到错误位置。**必须肉眼确认。**

### 4. 使用

`run2.sh` 就是控制台：

```bash
./run2.sh on        # ★开启：游戏一开就自动跑，退出就停
./run2.sh off       # ★关闭
./run2.sh status    # 看状态（守护/bot/游戏）
./run2.sh logs 50   # 看日志
./run2.sh play 20   # 手动跑 20 步
./run2.sh dry 3     # 只识别不点击（验证识别）
```

**不想用了怎么关**：
| 场景 | 做法 |
|---|---|
| 临时 | `./run2.sh off` |
| 永久 | `./run2.sh off` 然后重启机器（守护是临时单元，不自动启动） |

## 二、游戏模式开关（Decky 插件）

**游戏模式没有终端**，所以做成 Decky 插件。

### 前提

已安装 [Decky Loader](https://github.com/SteamDeckHomebrew/decky-loader)。

### 构建

```bash
cd decky-plugin/BJBot
npm install          # ⚠️ arm64 机器需把 @rollup/rollup-linux-x64-gnu 换成 arm64-gnu
npm run build        # → dist/index.js
node verify.mjs      # ★ 隔离验证，6 项必须全过
```

### 安装

```bash
sudo cp -r . /home/deck/homebrew/plugins/BJBot
sudo chown -R deck:deck /home/deck/homebrew/plugins/BJBot
sudo systemctl restart plugin_loader
```

### 使用

游戏模式 → 按 `...` 打开侧边栏 → 找到 **BJBot** → 点「开启 bot」。

### 回滚

```bash
bash rollback.sh     # 移出插件 + 重启 loader + 报告健康状态
```

## 三、其他 Linux 机器

### 能装在哪

**不是只有 Steam Deck。** 要求：

| 要求 | 必要性 |
|---|---|
| 游戏跑在 Linux（原生或 Proton/Wine） | 必须 |
| **PipeWire** | **必须（主要门槛）** |
| python3 + numpy/evdev/Pillow | 必须 |
| gstreamer + gst-plugin-pipewire | 必须 |
| `/dev/uinput` 可写 | 必须 |
| xdotool | 可选 |

### 换机器必须改两处

**① 棋盘标定**
```bash
python3 calib.py     # 分辨率不同必须重做
```

**② PipeWire 节点号**
`capture_pw.py` 里的 `path=93` 是机器相关的：
```bash
pw-cli ls Node | grep -A2 "node.name"     # 找游戏的视频流
# 或
gst-device-monitor-1.0 Video
```
把 `path=93` 换成新编号。

**未知数**：无 PipeWire 的纯 X11 机器需改抓帧实现（`python-xlib` / `mss`），**未实测**。

## 四、是否必须装高清补丁

**不是必须，但换画质必须重新标定。**

`vision_np.py` 的颜色阈值是按 **1280×800 + 汉化高清补丁** 实测标定的。

| 情况 | 能否用 | 要做什么 |
|---|---|---|
| 1280×800 + 高清补丁 | ✅ 直接可用 | 无 |
| 同分辨率、无补丁（原版素材） | ⚠️ 可能要调 | `calib.py` 看未知格；多则重调颜色阈值 |
| 其他分辨率 | ⚠️ 需标定 | `calib.py --save` 后验证 64 格识别 |
| 其他语言版 | ⚠️ 通常可以 | 视觉不看文字，但菜单按钮位置可能不同 |

**唯一可靠判据**：
```bash
./run2.sh dry 3       # 看"未知格"是否为 0
```

## 五、故障排查

| 现象 | 原因 / 解决 |
|---|---|
| 提示"抓帧失败" | PipeWire 节点号变了，或 `XDG_RUNTIME_DIR` 没设 |
| **分数不涨、反复走同一招** | **标定没对准**（跑 `calib.py` 看 overlay 图） |
| bot 不动 | `./run2.sh status`；看 `./run2.sh logs` |
| 卡在弹窗上 | 内置抗遮挡会自动尝试关；不行手动按 ESC |
| 换关卡后失效 | 关卡背景变化大 ⇒ 重新 `calib.py` 确认 |
| 想让它跑更快 | **别调** —— 已到物理上限，再快就是假速度（丢步） |
| 插件面板空白 | 检查 `node verify.mjs` 是否全过；`rollback.sh` 回滚 |

### ⚠️ 已知限制

- **不要用 `sudo` 跑 bot** —— 会清掉 `XDG_RUNTIME_DIR` 导致 PipeWire 失败
- **`pkill -f` 在 SSH 里会自杀** —— 如果 pattern 匹配到自己的命令行，用 `[x]` 转义
- **绝对定位鼠标不生效** —— 必须用 `vmouse2.py`（相对移动）

## 六、配置项

`bot/bot_v6.py`：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--engine` | `pro` | `pro`（推荐）/ `fast` |

| `--vision` | `vision_np` | 识别后端 |
| `--moves` | 0 | 步数（0=一直跑） |
| `--out` | — | 结果 JSON 输出路径 |
