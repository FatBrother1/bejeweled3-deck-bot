# 哪些我没验证过

写这个是为了避免误导。下面这些是理论上可行但我没在真机上试过的，
如果你要在类似环境里用，心里有个数。

## 没验证的

非 Steam Deck 的 Linux 机器。整个开发过程都在 Steam Deck 上做的，
别的发行版能不能跑我不知道，虽然依赖看着都通用。

没有 PipeWire 的环境。现在的抓帧代码只支持 PipeWire，
纯 X11 得改成 `python-xlib` 或者 `mss`，那部分我没写。

其他分辨率。标定是按 1280x800 做的，换个分辨率得重跑 `calib.py`，
但重跑之后识别准不准我没试过。

原版低清素材。颜色阈值是按汉化高清补丁调的，换回原版可能得重调。

长时间运行的稳定性。最长连续跑过 100 步，小时级别的没试过。

多显示器或者非标准的 gamescope 配置。

## 验证过的

Steam Deck 加 SteamOS，全程在这上面开发。

PipeWire 抓帧，90.7 帧每秒，一帧 11.07 毫秒。

uinput 相对移动鼠标，30/30 成功。

100 步长跑，98 步有效，净得 14900 分。

Decky 插件在游戏模式里，用户实测验收通过。

标定工具，64 格全部识别成功。

## 你自己怎么判断

```bash
cd bot
./run2.sh dry 3
```

这个命令只识别不点击，看输出的未知格数量。

零个就说明环境没问题。一到三个可能是道具特效，勉强能用。
超过三个就是标定或者颜色阈值不匹配，得调。

如果连这个都跑不起来，比如抓帧直接失败，那就是环境不满足要求，
看 `安装与使用.md` 里"其他 Linux 机器"那一节。

游戏模式方面，经典和禅意模式验证得比较充分，闪电模式只验证了一部分，
牌局模式的求解器不适用（那个模式要凑扑克牌型，不是消除得分）。
