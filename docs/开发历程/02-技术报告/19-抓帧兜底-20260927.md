# 抓帧兜底修复（PipeWire 节点消失导致 bot 变瞎）

2026-09-27。用户点名「修复啊」。

## 1. 现场

13:34:14 起，日志里每隔约 10 秒一条 `抓帧失败: None` / `抓帧失败: eof`，
一直到 14:32 都这样。守护一直在拉起 bot，bot 一起来就死，等于永远瞎着。

查证（当时）：

- 游戏进程 **Sep 25 16:12 起就没重启过** —— 不是游戏重启导致的；
- `pw-dump` 里**一个 `Video` 类节点都没有**，`pw-cli info 93` 报 `no global 40/41/61/64`；
- 但 `gamescopectl screenshot` 还能抓到帧（实测 `cap2.get()` 返回 `(800,1280,3)`）——
  说明画面还在，只是 PipeWire 那条路断了。

## 2. 根因（三个洞，第一个是今天撞上的，后两个是翻代码翻出来的）

引擎原来是这么写的（`bot_v6.py`）：

```python
cap = PwCapture()                      # capture_pw.py，里面 path=93 写死
if not cap.start(): log("抓帧失败: %s" % cap.err); return
```

1. **`path=93` 写死**。节点 id 不是常量，换会话就可能变；节点整条消失时更是一个都没有。
   `cap.start()` 拿不到首帧 → 返回 False → 打一行日志就 `return`，进程直接退出。
2. **运行中坏掉时，`PwCapture.get()` 返回的是"最后一帧"而不是 None**
   （`get()` 超时后 `return self.latest.copy()`）。也就是说：如果流是在运行中途断的，
   画面会**冻在最后一帧**、bot 会以为游戏暂停，而"拿不到帧就退兜底"这个判断永远不会触发。
   今天没撞上这个形态（今天是一开始就起不来），但它迟早会撞。
3. **退到兜底后永远回不来**。就算节点回来了，也没人会再试一次。

另外，`cap2.py` 里其实**早就有**"PipeWire 失败退 gamescopectl"的现成实现
（`poker.py`、`which_mode.py` 读单帧时用它），只是引擎没用 —— 引擎直接用了更底层的 `PwCapture`。

## 3. 改动（4 个文件）

| 文件 | 改了什么 |
|---|---|
| `capture_pw.py` | 新增 `find_video_node()`：从 `pw-dump` 里按 `media.class == "Video/Source"` 找节点（点名 gamescope 的优先），找不到返回 None。`PwCapture(path=None)` 默认自动发现、发现不到才退回 93（显式传 path 的老调用不受影响）。`start(wait=8.0)` 加了等待参数，回试时用 1.5 秒不用等 8 秒。 |
| `cap2.py` | 重写为完整的兜底件：运行中检测（`err` 置位 / 线程退出 / 连续 5 次拿不到新帧）、发现就切 gamescopectl 并**丢掉那帧旧画面**、在兜底路径上每 60 秒回试一次 PipeWire、节点回来自动切回 90fps。新增 `start()`（引擎启动检查：PipeWire 不行就确认兜底真能出图）、`backend`、`err`、可选 `log` 回调。 |
| `bot_v6.py` | 抓帧入口从 `PwCapture()` 换成 `Cap(log=log)`；启动检查改成"两条路都不行才 return"，并打印 `抓帧后端: PipeWire / gamescopectl`。 |
| `install.sh` | 补三个漏掉的硬依赖：`cap2.py`（本修复的入口，不装起不来）、`reader_mem.py`（`--vision auto/mem` 的内存后端）、`which_mode.py`（`watch2.py` 靠它认模式）。前两个是这次点名范围内的必需项，第三个是之前就记着的 P2。 |

`modes/`、`solver_*`、`poker.py`、其余七个模式**一行未动**。

## 5. 顺手记下的一条新事实

`gst-launch-1.0 pipewiresrc path=9999`（一个不存在的节点号）**照样能连上并出帧**
（实测 4 秒 361 帧）—— 说明 `path` 无效时 pipewiresrc 会连默认节点，
**节点号不是"能不能出帧"的唯一变量**；真正会失败的是"一个视频源都没有"。
所以写死 93 的锅是"节点号会变"，而 13:34 那次瞎掉的主因是节点整条消失。
两者都由这次的自动发现 + 兜底覆盖。
