# 牌局模式自动续局实现报告

2026-09-24

## 做了什么

牌局模式会死 —— 凑出带骷髅标记的牌型要抛硬币，翻到骷髅就结束。
现在死了会自动点「再玩一次」继续，不需要人守着。

```bash
python3 bot_v6.py --mode poker --auto-restart
```

实测已经连续自愈 2 次（死亡 2 次、续局 2 次）。

---

## 判断"游戏结束了"踩的两个坑

### 第一个坑：用错了信号

我最初用 **Board 指针归零** 当判据，理由是"游戏结束时 Board 对象会被销毁"。

**实测证明这是错的。** 停在「最终得分 60,500」结算画面时：

```
gApp  = 0x01924758
Board = 0x4AD01138    ← 非零，依然有效
```

结算画面上 Board 指针**仍然有效**，只是里面的数据冻结了。

### 第二个坑：检测代码放在了不会被执行的分支里

更糟的是我把检测写在了 `if g is None:`（读不到棋盘）那个分支里。
而结算画面上**棋盘是能读到的**（Board 指针有效、返回冻结的棋盘），
所以 `g is None` 不成立，那段代码**从来没被执行过**。

症状：bot 对着结算画面一直"下棋"——反复算同一招、手牌恒定不变：

```
手牌 ?OOOO  目标色=O  走 (0,3)<->(1,3)
手牌 ?OOOO  目标色=O  走 (0,3)<->(1,3)    ← 一模一样
...
手牌 ?OOOO  目标色=O  走 (0,3)<->(1,3)
```

速度掉到 **0.22 步/秒**（正常是 1.2），而且手牌在读同一个冻结值。

### 修法

判据改用**画面**：结算画面是一整块橙色面板。

```
顶部「最终得分」横幅区  RGB(202,141,84)
中部棋盘区被面板覆盖    RGB(208,158,91)
```

两者都是明显的 R > G > B（橙棕色调）。游戏中棋盘区是深蓝紫背景加彩色宝石，
不会有这种整体橙棕。

用 5 张真实截图验证：

| 截图 | 实际状态 | 判据输出 |
|---|---|---|
| state2.png | 结算 | **True** ✓ |
| now_00.png | 结算 | **True** ✓ |
| poker2.png | 游戏中 | False ✓ |
| go1.png | 游戏中 | False ✓ |
| pk4.png | 游戏中 | False ✓ |

位置也改了：检测现在放在**主循环每一轮的开头**，而不是某个条件分支里。

## 「再玩一次」按钮位置

从实拍结算画面标定（1280×800）：

| 按钮 | 坐标 |
|---|---|
| 徽章 | (433, 738) |
| **再玩一次** | **(640, 738)** |
| 主菜单 | (847, 738) |

点击后等最多 12 秒，每 0.5 秒检查一次画面变回游戏状态，
确认新局真的开始了才继续；如果 12 秒后还在结算画面就再点一次。

## 进程存活问题

之前用 `nohup` 在 SSH 里起 bot，**SSH 一断进程就死**。这个坑我踩了两次，
两次长时测试都因此半途而废。

现在用 `systemd-run --user` 起独立单元：

```bash
systemd-run --user --unit=bjbot \
  --setenv=XDG_RUNTIME_DIR=/run/user/1000 \
  --setenv=DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/1000/bus \
  --setenv=PATH=/usr/bin:/bin \
  --working-directory=/home/deck \
  /usr/bin/python3 /home/deck/bot_v6.py --vision mem --mode poker --auto-restart
```

日志进 journal，断开 SSH 不影响：

```bash
journalctl --user -u bjbot -f          # 实时看
systemctl --user stop bjbot            # 停
```

## 验证过程

起动时游戏正停在结算画面（`screen_is_gameover = True`）。日志：

```
02:51:46   内存后端: PID=19271 gApp=0x01924758 Board=0x34076980
02:51:48   起始分=32900
02:51:48   ★ 检测到游戏结束（结算画面）
02:51:50   已点「再来一次」，新局已开始
02:51:51   #1 (4,5)<->(5,5) 预测=150  ✓ [0.84步/秒]
```

Board 指针从 `0x4AD01138` 变成了 `0x34076980` —— 新局确实分配了新的棋盘对象，
不是旧数据。

之后连续运行，已经自愈 2 次：

```
检测到结束次数: 2
成功续局次数:   2
```

速度 1.21 步/秒，期间打出过四条（30000 分）、葫芦、两对等牌型。

## 已知限制

- **只验证了牌局模式的结算画面。** 普通模式（经典/禅意）的结束画面可能不同
  （经典模式是"没有可行走法"，禅意永不死），当前判据不保证适用于它们。
- **按钮位置是硬编码的。** 如果游戏分辨率变了、或换了语言版本，需要重新标定。
- **续局后不记录上局战绩。** 现在只把上一局的起始分打回日志，
  没有累积每局的最终得分做统计。
