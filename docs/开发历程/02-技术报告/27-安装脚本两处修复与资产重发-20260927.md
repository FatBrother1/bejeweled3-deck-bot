# install.sh 两处修复 + 资产重发（2026-09-27）

## 起因

Deck 上线后做发行包干装验收，`install.sh` 又暴露两处缺陷，都不在上一轮修复的范围内。
两处是同一类毛病：**文档里写的用法能跑，换个同样自然的调用方式就半装**。

## 缺陷一：相对路径 —— 从包目录外调用会半装

脚本用 `HERE` 定位源目录，但下面这两处用的是**相对路径**：

- `for f in modes/*.py`（拷贝模式包）
- `cp board.json "$TARGET/bjbot/board.json"`（棋盘几何）

脚本自己不 `cd`，所以从别的目录调用（`bash /路径/bot/install.sh /目标`）时，glob
匹配不到 ⇒ `cp` 失败 ⇒ `set -e` 把安装**中断在第二步**。

Deck 实测（目标指向 `/tmp`）：

| 调用方式 | 退出码 | 落地文件 | `modes/` |
|---|---|---|---|
| `cd 包目录 && bash install.sh 目标` | 0 | 38 | 10 |
| `cd 别处 && bash 包目录/install.sh 目标` | **1** | **23** | **0** |

装出来 `modes/` 是空的 ⇒ `bot_v6.py` 第一件事就是 `import modes` ⇒ 起来就 ImportError。
README 写的用法（`cd bejeweled3-deck-bot/bot && bash install.sh`）不受影响，但
`bash ~/下载/bot/install.sh` 这种写法会得到一个坏安装，而且退出码 1 之前已经拷进去
23 个文件，容易看着像"装好了"。

**修复**（提交 `62f113e`）：算完 `HERE` 就切过去，并把 `TARGET` 先转成绝对路径，
免得相对目标被这次 `cd` 改变含义。

```bash
case "$TARGET" in /*) ;; *) TARGET="$PWD/$TARGET" ;; esac
cd "$HERE"
```

## 缺陷二：第 12~13 行写死 `/home/deck`

```bash
mkdir -p /home/deck/bjbot
[ -f /home/deck/bjbot/autorestart ] || echo 1 > /home/deck/bjbot/autorestart
```

这两行**不看 `TARGET`**。在非 Deck 机器上跑文档里那句 `bash install.sh /path`，
第一行就 permission denied、被 `set -e` 中断 ⇒ 「装到指定目录」实际只在 Deck（或 root）
下能用。

**修复**（提交 `5423fdb`）：改成 `"$TARGET/bjbot"`。Deck 上 `TARGET` 默认就是
`$HOME=/home/deck`，行为与原来完全一致。

## 验证方法上的两条新经验

1. **`api.github.com/.../releases/download/...` 不是下载路由**，会回一个 4KB 的错误页
   （sha256 恒为 `edbd0367cec8…`）。下载只能用 `browser_download_url`
   （即 `github.com/<owner>/<repo>/releases/download/...`）。本轮在这个坑里栽了两次，
   两次都误报成「线上与本地不一致」。
2. **GitHub 现在给资产返回 `digest: sha256:…`** ⇒ 不用下载就能核对资产字节。本轮靠它
   定案：整仓包一次下载只拿到 1044480 字节（3.2MB 的包在这条线路上会截断），sha256 对
   不上、zip 也打不开，看起来像"上传坏了"，其实是下载断了 —— 拿 `digest` 一比就知道
   线上是好的。

## 附：观察到的牌局「无走法风暴」

验收时顺带看到 Deck 上牌局每 1~2 分钟重启一次。查下来是一条**自己设计出来的退出路径**
被高频触发：

- `modes/poker.py` 的 `DEAD_EXIT_AT = 30`：连续 30 次无招就退出，让守护重新拉起
  （普通模式是就地待命、不退出）；
- 无招的判据是 `rank_moves_poker` 返回空表 —— 它枚举所有合法交换，要求模拟后
  `total > 0`，一个都没有就是空；
- 而 `bot_v6.py:830` 会把**拉黑计数 ≥ 3 的格子改成 `"?"`**，牌局求解器又**跳过任何
  涉及 `"?"` 的交换** ⇒ 拉黑攒到一定程度，掩码棋盘上就没有合法交换了。

日志侧的对应：`bot.out` 里 36 次完整风暴，每次 30 次无招、耗时 36~38 秒，紧接着
`watch.log` 一行「检测到游戏启动 -> 拉起 bot_poker.py」；每次风暴前的现场都是一串
`✗拉黑`，单周期有效率约 54%。重启会清空拉黑，于是又打一阵、再攒满、再退出 —— 这就是
那个 1~2 分钟的周期。
