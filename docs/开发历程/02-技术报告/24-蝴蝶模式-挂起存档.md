## 一、这一轮查到的东西（关键，别丢）

### 1. ★ 蝴蝶宝石 = 状态位 `128`（0x80）—— 已目视核实

`reader_mem` 里 `Piece+0x228` 的状态位，蝴蝶模式下会多出 `128`。
实测抓到 4 只：`(3,1) (4,6) (6,2) (7,6)`，全部都在棋盘下半部（"蝴蝶从底下出现"），
裁图放大看**四张全是带蝴蝶翅膀的宝石**（橙、粉、橙、白）。

⇒ **优先消蝴蝶的逻辑已经有了数据基础**：`f & 128` 就是蝴蝶格。

### 2. ★ 游戏窗口失去焦点会被暂停 —— 这次"bot 卡死"的主因

症状：棋盘冻住（分数 6,275 十分钟不变）、蝴蝶不飞、所有拖动全被拒。
真相：**游戏窗口丢了焦点 → Bejeweled 3 自动暂停**（画面照旧渲染、不显示暂停界面）。
我点了一下游戏内"菜单"把焦点抢回来，游戏立刻继续，蝴蝶马上飞到顶 → 结算
（最终得分 53,775、已释放蝴蝶 17、总时间 18:47）。

⇒ 排查这类"点了没反应"时，**先确认游戏有没有焦点**，别急着怀疑几何/坐标。

### 3. ★ 上一轮加的"全 ban 解禁"兜底有 bug（用错了棋盘）

```python
if not rk and (banned or banned_sticky):
    rk_free = solver_pro.rank_moves(g, timeqems=tg, banned=set(), flags=fl)   # ← 用了掩码后的 g
```
掩码（`?`）才是杀死候选的元凶，所以"解 ban 但仍用掩码棋盘"救不回来。
实测：08:44 起棋盘上只剩 3 个合法走法 `(1,0)↔(1,1)`、`(1,1)↔(2,1)`、`(1,2)↔(2,2)`，
**三个全都涉及被掩码的 (1,1)** ⇒ 求解器 0 候选 ⇒ bot 趴窝 15 分钟。
**修法**：这一层兜底也必须用 `g_raw`（并且顺手 `blacklist.clear()`）。

### 4. 蝴蝶模式的棋盘几何：**存疑，未定论**

一次控制变量 A/B（同一走法、只改 y0）显示：`board.json`(y0=79) 拖动**被拒**、
`y0≈104` **接受**（变化 8 格）—— 像是棋盘比经典低约 25px。
但后面再扫时游戏已被暂停（见第 2 条），**那批"全被拒"的数据全部作废**。
⇒ 这个结论**不能算数**，等下次游戏有焦点时重做。

### 5. 玩家面板（`which_mode.py`）现在是对的

v0.2.13 已修：六个模式的 `[Board+0x0]` 全量重测 + 无棋盘对象时如实报"菜单"。
蝴蝶模式实测显示"蝴蝶" ✅
