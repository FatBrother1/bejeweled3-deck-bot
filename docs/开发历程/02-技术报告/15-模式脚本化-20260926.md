## 〇、为什么要做

蝴蝶、钻石矿、闪电、牌局四个模式的修复，一直全塞在 `bot_v6.py` 一个文件的
if 链里，靠棋盘特征倒推模式。四个模式的判据挤在一起，隐式耦合。

**牌局这次就是证据**：修钻石矿时加的 `if nd > 0: 棋盘判据 else: 分数判据`，
把牌局留在了错的分支里 —— 牌局消除宝石不给分，于是每一步真有效的交换都被判
"被拒"。这不是巧合，是结构问题：**判据写在一起，就一定会有人漏在分支外。**

还有一个更该说的：原来有**两套互不相干的模式检测**。`which_mode.py` 基于内存
`[Board+0x0]`，认得出 7 个模式、每条都对着画面核过，但**只喂给插件面板显示** ——
`bot_v6.py` 里 grep `which_mode` 是零命中。bot 自己那套 `detect_mode()` 只区分
"牌局 vs 普通"。面板写着"现模式＝蝴蝶"，bot 走哪条策略是另一套判据说了算。

## 一、现在的结构

### 引擎（`bot_v6.py`）

只剩跟模式无关的东西：循环、抓帧、内存读盘、鼠标、暂停自愈、结算检测。
它不认识任何具体模式，每步构造一个 ctx 交给注册表：

```python
ctx = {"g":…, "g_raw":…, "blacklist":…, "banned":…, "banned_sticky":…,
       "extra":…, "nd":…, "frame":…, "log":…, "get_frame":…}
res = mode.choose(ctx)          # None = 这步无招
```

改造后，引擎里**一条 `nd > 0`、`butterflies`、`timegems` 的判断都没有了**，
只剩牌局那个画面 hint（那本来就是画面判据，归引擎）。

### 模式（`modes/<key>.py`，一个模式一个文件）

每个文件只声明它跟别人不一样的地方，其余继承 `modes/base.py`：

| 声明 | 含义 |
|---|---|
| `KEY` / `NAME` | 标识 / 显示名 |
| `GEO` | 用哪份棋盘标定（`board_<GEO>.json`） |
| `EFFECTIVE` | `"score"` 靠分数变化判交换生效；`"board"` 靠棋盘变化判 |
| `DEAD_EXIT_AT` | 连续无招多少次退出；`None` = 就地待命 |
| `detect(ctx)` | 从棋盘特征认出自己 |
| `choose(ctx)` | 选一步 |
| `on_board_info` / `on_picked` / `on_no_move` | 各自的日志 |
| `settles_on_clock_freeze(ctx)` | 时钟冻结时认领"这是本局结束" |

八个模式：`classic` `zen` `lightning` `icescape` `butterfly` `diamond`
`poker` `quest`。

| 模式 | GEO | EFFECTIVE | 备注 |
|---|---|---|---|
| 牌局 poker | poker | board | 消除不给分；手牌从左往右填 |
| 钻石矿 diamond | diamond | board | 分数内存里读不到；时钟冻结自己认领结算 |
| 蝴蝶 butterfly | butterfly | score | 棋盘低 58px；蝴蝶飞到顶行结束 |
| 闪电 lightning | classic | score | 时间宝石优先 |
| 冰风暴 icescape | classic | score | **空的**：还没有针对它的策略 |
| 禅意 zen | classic | score | **与经典同策略**，先占位 |
| 任务 quest | classic | score | **空的，而且现在也选不中**（检测认不出） |
| 经典 classic | classic | score | 兜底 |

### 入口（`bot_<key>.py`，八个薄壳）

每个等价于 `bot_v6.py --mode <key>`，负责把模式钉死。守护按检测结果拉起对应的
那一个，插件面板上也就有了真实的脚本名可显示。

### 守护（`watch2.py`）

原来写死 `bot_v6.py --mode auto`（一个脚本自己猜）。现在：

```
检测到蝴蝶 -> bot_butterfly.py        检测到牌局 -> bot_poker.py
检测到经典 -> bot_classic.py          ……
认不出来   -> bot_v6.py --mode auto（退回引擎自己认）
```

运行中模式变了也会换脚本，**加了两拍防抖**（转场那几帧认花一次不会触发重启）。

### 插件（`main.py`）

面板的"启动脚本"那栏改成从**实际在跑的进程**读（`pgrep -af`），不再写死常量。

## 二、验证

### 离线 36/36（`test_modes.py`，Deck 上跑）

要证的核心只有一条：**拆成八个模式文件之后，引擎行为没变。**

- 注册表：8 个模式全加载，KEY/NAME/GEO/EFFECTIVE 齐全
- **几何映射与旧 if 表逐项一致**（含"有泥优先于蝴蝶"）
- **有效判据与旧条件 `nd>0 or poker` 逐项一致**（4 组）

## 三、要说明的三件事

**① 冰风暴和任务这两格是空的。** 冰风暴没有任何针对它的策略（连参考图都没有，
模式检测那一轮就记着这个缺口），任务连检测都认不出（任务界面没有棋盘对象，
会显示成"菜单"）。我按"不猜需求"的原则只把位置占住、没编策略 —— 以后要补，
改对应的那个文件就行，不用再动引擎。

**② 禅意现在与经典同策略。** 两者棋盘版式完全相同、求解器也一样。禅意那一格
先占着，以后要做成"不追求单步分、追求局面稳"的话，改 `modes/zen.py` 即可。

**③ 一处日志变了。** 普通模式死局现场原来会打 `tg=%s`（时间宝石），现在时间
宝石是模式内部的事、引擎不再持有，那一项去掉了，其余原样。
