# 25 · 安装清单修复（2026-09-27）

开发历程上一版（v2.0.0 那份资产盘点）顺手核了一遍 `bot/install.sh` 的部署清单，发现它和
现实对不上，而且对不上的方式有两种。这一轮把它修了，提交 `9924d9d`。

## 现象

`install.sh` 负责「从零装一台」：检查依赖 → 复制文件并把脚本里写死的 `/home/deck`
改成实际目录 → 建棋盘目录 → 自检。它的部署清单（那个 `for f in ...` 循环）里：

1. **漏了四个文件**：`poker.py`、`solver_poker.py`、`calib.py`、`solver_fast.py`。
2. **有一个文件根本不存在**：`which_mode.py` 被写在清单里，但 `bot/` 目录下没有这个
   文件 —— 仓库里只有 `decky-plugin/BJBot/which_mode.py` 一份（插件和守护共用）。

## 根因

第 1 条的隐蔽之处在于 `modes/poker.py` **不是在顶层 import** 这两个文件的：

```python
def choose(...):
    ...
    import poker          # 第 43 行附近
    import solver_poker   # 第 72 行附近
```

所以装完启动不报错、跑普通模式也不报错，**跑到牌局模式才 ImportError**。`calib.py`
是 README 里要求换机器/换分辨率时跑的标定工具，`solver_fast.py` 只影响
`--engine fast`（默认是 `pro`），这两个漏了不炸但少功能。

第 2 条更狠。`copy_one` 打不开源文件就 `return 1`，而脚本开头是 `set -e`：

```bash
copy_one() {
  ...
  python3 - "$src" "$dst" "$TARGET" <<'PY' || { echo "   ❌ $f 处理失败"; return 1; }
  ...
}
```

于是安装会**直接中断在 `which_mode.py` 这一步**，后面的 `watch2.py`、`run2.sh`、
`modes/*.py`、棋盘几何全都没装。这不是"某个模式坏掉"，是整个装不完。
（第 22 轮补 `cap2.py` / `reader_mem.py` / `which_mode.py` 时，前两个是真的在 `bot/`
下，第三个不是 —— 当时没人核过源文件在不在。）

## 改动

只动 `bot/install.sh` 一个文件（+25 / −2 行）：

- 部署清单补 `poker.py`、`solver_poker.py`、`calib.py`、`solver_fast.py`；
- `which_mode.py` 从清单里拿掉，改成单独一段：先在 `bot/` 找，再在
  `../decky-plugin/BJBot/` 找，两处都没有只警告不中断（守护会退回 `--mode auto`，
  能跑但认不出模式）。它内部有 4 处写死的 `/home/deck`（`sys.path.insert`），
  所以必须走 `copy_one` 的路径改写，不能直接 `cp`；
- `copy_one` 支持显式传源路径（第二个参数，默认行为不变）。

## 验证（离线，两条独立证据）

1. `check_install.py`（本轮新增）：检查清单里的文件是否都存在 + 部署出去的那些
   `.py` 的 import 能不能在部署集合里找到（stdlib / 第三方 / 同目录 / `modes` 包
   都算找得到）。拿**修复前**的 `install.sh` 跑，报 3 个 import 缺失
   （`solver_fast` / `poker` / `solver_poker`）加 `which_mode.py` 不存在；拿修复后的
   跑，通过。它顺手报出一个可选项 `vision_np2`（只在 `--vision vision_np2` 时
   import，仓库里从来没有这个文件，属"没实现的功能"不是"清单漏了文件"）。
2. `dryrun_install.sh`（本轮新增）：把 `install.sh` 里「② 复制文件」整段源码抠出来、
   目标指向临时目录跑一遍（测的是上机跑的那段源码，不是副本）。38 个文件全部落地
   （22 个脚本 + 10 个模式 + `which_mode.py` + 5 份棋盘几何）、退出码 0、
   `which_mode.py` 里 `/home/deck` 残留 0 处 / 改写 4 处、`run2.sh` 有可执行位。

两条脚本与它们的输出都在 `输出/2026-09-26/bejeweled/安装缺口修复/`。

## 影响面

- **Deck 上的现装不受影响**：历轮都是手动传的文件，`bot/` 下该有的都在，`install.sh`
  本身也不参与运行（只在重装时才用）。
- 受影响的是**从零装一台**：修之前装不完（第 2 条）或牌局坏掉（第 1 条）。
