# 钻石矿「重复点击空转」修复报告

日期：2026-09-26 00:25
设备：Steam Deck（deck@192.168.3.11），Bejeweled 3，1280x800，钻石矿模式

## 一、现象（用户报的）

bot 在钻石矿里对着同一个走法反复点击，棋盘毫无变化。日志实锤（修复前）：

```
23:58:44   #280 (1, 5)<->(2, 5) 预测=100   实际=0      ✓ [7.19步/秒]
23:58:46   #281 (1, 5)<->(2, 5) 预测=100   实际=0      ✓
...
00:01:43   #411 (0, 2)<->(1, 2) 预测=150   实际=0      ✓ [4.98步/秒]
```

同一招连点 35 步、全部标 ✓（判定为"有效"）、分数一点不动。

## 二、根因（两个，缺一不可）

### 根因 A（主因）：钻石矿的棋盘格子位置和 board.json 不一样

`board.json` 是经典/禅意模式标定的，钻石矿的棋盘在屏幕上的位置**完全不同**：

| | x0 | y0 | pitch_x | pitch_y |
|---|---|---|---|---|
| board.json（经典/禅意） | 476.0 | **79.0** | 89.17 | 88.17 |
| **钻石矿（本次实测）** | **469.0** | **133.1** | **85.25** | **84.50** |

钻石矿比经典**低约 54px**、格距也小一点（矿坑上方有装饰框）。

后果：bot 按自己的棋盘算出合法交换，但拖动落点是按旧几何算的 ⇒ **落到错误的两格**上
⇒ 游戏认为这不是合法交换 ⇒ 原样弹回 ⇒ 棋盘一动不动。

决定性 A/B 实测（同一盘面、同一走法）：

| 用的几何 | 拖动像素 | 结果 |
|---|---|---|
| board.json | (833,255) → (833,344) | 棋盘**变化 0 格**（被拒） |
| 实测标定 | (809,304) → (809,388) | 棋盘**变化 12 格**（接受） |

标定方法：同时抓帧 + 用 `reader_mem` 读真实棋盘，网格搜索让每格采样色最接近的
x0/y0/pitch_x/pitch_y。多次拟合结果稳定（y0 131~133、py 84.3~86、x0 463~469、px 83.8~85.3），
最优一组逐格色距 12.6（旧几何 237.5）；画网格回实况帧目视核对：新几何的点落在宝石正中，
旧几何的点落在格子缝里。

### 根因 B（放大器）：判「这步生效没有」的指纹取自被改写的棋盘

`bot_v6.py` 里"拉黑"会把某些格子改写成 `'?'`：

```python
for (i, j), n in list(blacklist.items()):
    if n >= 3: g[i][j] = "?"
...
f0 = rd.mod.fingerprint(g)          # ← 用的是改写后的 g
...
changed = fingerprint(g2) != f0     # g2 是原始读数 ⇒ 必然"变了"
```

只要有一个格子被拉黑（计数 ≥3），`f0` 里那格是 `_`、而下一帧原始读数是真宝石
⇒ **每一步都判"棋盘变了"**。钻石矿又恰好用 `effective = changed`（分数读不到，
只能靠棋盘变化判）⇒ 假有效 ⇒ `banned.clear()` ⇒ 同一招无限重选。

时间线吻合：`#272~#279` 连续 8 步 ✗ 把 `(2,3)` 的拉黑计数推到 3 ⇒ `#280` 起进入死循环。

## 三、改了什么（bot/）

| 文件 | 改动 |
|---|---|
| `bot/board_diamond.json` | **新增**：钻石矿棋盘标定（x0=469.0 y0=133.1 px=85.25 py=84.50） |
| `bot/bot_v6.py` | 像素几何按模式切换：本局第一次读盘时，有泥土 ⇒ 钻石矿 ⇒ 用 board_diamond.json；否则用 board.json |
| `bot/bot_v6.py` | `f0` 改用**原始棋盘**指纹（根因 B） |
| `bot/bot_v6.py` | 钻石矿有效判据加 `swapped`：我们拖的那两格确实变了才算有效 |
| `bot/bot_v6.py` | **连续被拒保护**：连续 12 步没被接受就停手等待（棋盘自己变了或 20 秒超时再试），不再盲目重试 |
| `bot/install.sh` | 一并安装 board_diamond.json（已有则不覆盖） |

经典/禅意路径不受影响：`board_classic.json` 不存在 ⇒ 回退 board.json ⇒ 与改动前逐字节同行为。

## 五、遗留 / 待确认（没动）

1. **钻石矿的分数读不到**：画面 $104,500 时 `Board+0xD24` 读 0 ⇒ 日志里"实际"列在
   钻石矿永远是 0。现在判有效不依赖分数（靠棋盘变化 + 两格变化），所以不影响行为，
   但日志看不出真实进度。
2. **经典/禅意未实机复测**（这次没切模式）：代码路径上是回退 board.json，与改动前一致。
3. **其它模式（蝴蝶/冰风暴）的棋盘几何未标定**：若它们的格子位置也不同，会出现同样的
   拒绝；现在至少不会无限空转（连续被拒会停手并打日志）。
4. **cs_live 活跃标记只写一次**：bot 进程跑满 10 分钟后标记过期，钻石矿的"时钟冻结"
   结束检测就失效（靠橙色结算面板兜底，实测能兜住）。
