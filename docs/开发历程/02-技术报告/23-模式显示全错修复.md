## 一、用户报的三个症状（全部复现并定位）

| 症状 | 真实原因 |
|---|---|
| 打开**钻石矿**显示"闪电" | 真正的钻石矿值 `0x8657D4` **压根不在映射表里**；而插件实际跑的那份 `which_mode.py` 是**旧版**（连泥土兜底都没有）→ 掉进图像指纹 → 撞上 `refs/mode_lightning.png` |
| **经典**显示"菜单" | `0x86511C` 是**经典**，旧表把它标成了 `menu` |

另外还查出一条用户没报但同样错的：**冰风暴显示"钻石矿"**（`0x8685EC` 是冰风暴，旧表标成 diamond）。

## 二、`[Board+0x0]` 到底是什么（这次才搞明白）

它是**棋盘对象的 vtable 指针**：

- 点进某个模式时，它**立刻**变成那个模式的值（连"继续游戏?"弹窗期间都已经是新值）
- 菜单/加载中**根本没有棋盘对象**，读不到（返回 None）
- 弹窗里会保留上一个已开局模式的对象 → 此时读到的是那个模式的值

## 四、改了什么

`decky-plugin/BJBot/which_mode.py`（同步部署到 `/home/deck/which_mode.py` 与插件目录两份）：

1. **MEM_MAP 只留六个对着画面核过的值**（旧表里的 `0x869364` 没核过，删掉）
2. 新增 **①c 分支**：读不到棋盘对象 = 在菜单/加载中 → 直接报「菜单」（`src="noboard"`），
   **不再交给图像去猜**（就是这一步在乱报蝴蝶/菜单）
3. 游戏没在跑 → 「未知」（`src="nogame"`）
4. 泥土 ≥4 → 钻石矿的兜底保留（`src="memboard"`）
5. 图像指纹降级为"有棋盘对象但值不认识"时的最后兜底
