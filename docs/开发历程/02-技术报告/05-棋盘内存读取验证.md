### ③ 分数：Steam 版确实用 `+0xD24`，不是 `+0xD28`

这一步等了很久才验上，因为一开始画面分数是 0，两个偏移都读出 0，没法区分。
让 bot 走了几步产生分数之后：

```
画面显示        850
[Board+0xD24]   850    ← Steam 版位置，对上了
[Board+0xD28]   0      ← Plus 版位置，是 0
```

**这就把 `+0xD24` 和 `+0xD28` 区分开了**，确认 Steam 版用前者。

### ④ 走步后实时变化

走一步，然后看内存：

```
走步前  分数 850    棋盘第一行第三列是橙
走一步  (3,6)<->(3,7) 预测 100 分
走步后  分数 950    3 个格子变了（正是消除的位置）
```

分数 +100 正好等于那一步的预测分，棋盘变化也落在正确位置。
**说明内存读取是实时的，不是缓存。**

注意最后两行：关卡实测 `[Board+0xE0C] = 1`，而画面显示"1 级"。
如果按 Steam 版文档的 `+0xE04` 读是 0。这两个偏移需要再确认一次——
可能在下一关才分得清。分数那条已经确认用 `+0xD24`。

## 遗留项

一处没分清：关卡的 `+0xE04` 和 `+0xE0C`。现在画面是 1 级，
`+0xE04` 读 0、`+0xE0C` 读 1。按分数的规律（Steam 用较小的那个偏移），
关卡应该也是 `+0xE04`，但它读出来是 0，和画面 1 对不上。

可能的情况：`+0xE04` 是内部值（从 0 计），画面显示要 +1，那 0 就对应 1 级，
也能自圆其说。要等进下一关才能确定。

不影响使用，因为棋盘和分数这两条最关键的已经完全确认。

## 安全性

整个过程**只用了 `process_vm_readv`**，没有调用任何写入函数，
没有调用游戏内部函数（`IsBoardStill` 那种要注入的没用），
没有用 sudo，没有改任何文件。

## 附：验证脚本

验证代码在 Deck 上以 heredoc 方式执行，未落盘成文件。核心逻辑：

```python
libc = ctypes.CDLL("libc.so.6")
libc.process_vm_readv.restype = ctypes.c_ssize_t

def rd(pid, addr, size=4):
    buf = ctypes.create_string_buffer(size)
    local  = I(ctypes.cast(buf, ctypes.c_void_p), size)
    remote = I(ctypes.c_void_p(addr), size)
    n = libc.process_vm_readv(pid, ctypes.byref(local), 1,
                                   ctypes.byref(remote), 1, 0)
    return buf.raw[:n] if n > 0 else None

gapp  = u32(pid, 0x008E1730)
board = u32(pid, gapp + 0xBE8)
piece = u32(pid, board + 0xF8 + 4*x + 32*y)
color = i32(pid, piece + 0x220)
```
