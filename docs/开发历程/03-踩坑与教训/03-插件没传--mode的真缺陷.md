# 插件没传 --mode 的真缺陷

## 现象

用户问：「bot 支持什么模式？模式之间会不会自动触发？为什么版本号不跟插件走？」
查证后 p1 是真缺陷，p2 是版本号混乱。

## 根因

三个启动入口全都没传 `--mode`：

| 入口 | 原命令行 | 后果 |
|---|---|---|
| `run2.sh` play/turbo/dry | `--engine pro --still-ms 250` | 用默认 normal |
| `watch2.py`（守护） | 同上 | 用默认 normal |
| Decky 插件 | 调 run2.sh | 用默认 normal |

于是插件路径下永远跑普通逻辑，而牌局模式要凑同花，不是每步分高。
我此前所有牌局测试都是手加 `--mode poker` 跑的，从没验证过插件路径。

## 怎么修的

`--mode` 默认值改成 `auto`，bot 自己识别模式。

判据迭代了两次。第一版看左侧取样区是不是绿色（G 是最大分量），失败 ——
那个颜色受游戏背景亮度影响，同一模式实测 RGB 从 (61,95,31) 变到 (90,81,30)，
后者 G<R 判据就失效。教训是不要用整体色调当判据。

第二版数牌局左侧 7 行分值表的绿色横条像素占比。牌局游戏中 0.348~0.461，
禅意/菜单 0.000，阈值取 0.2。区域 `x=250..430, y=180..460`，条件
`G > R+10 且 G > B+30 且 60 < G < 170`。在 185 张历史截图上回归：牌局 14 张全判对、
其余 175 张零误判，对 1024×768 缩放态也判对。

接线：`run2.sh` 的 play/turbo/dry 与 `watch2.py` 全部加 `--mode auto --vision mem`，
守护另加 `--auto-restart`。

## 连带的两件事

一、同步坑。我第一次提交只改了 Deck 上的副本，忘了同步回仓库，
等于这个修复没入库，第二个提交才补上。

二、版本号混乱。`plugin.json` 根本没有 version 字段（Decky 正是读它，
所以插件显示「无 version 字段」），版本号只在 `package.json` 里；
Release 已经打到 1.3.0、插件是 0.2.1，两套号并存。
用户选的处理是只把 v1.3.0 重命名成 v0.2.1，旧的 1.0.0/1.1.0/1.2.0 保留不动，
规则写进 README：版本号只有一个来源 = `plugin.json`。
装到 Deck 后日志显示 `Loaded BJBot (v0.2.1)`。

## 别再犯

只测手加参数的路径不算测过。真实入口（插件按钮、守护）必须各跑一遍。
判据不要用整体色调，要用某个模式独有的结构特征。
改了 Deck 上的文件，当场同步回仓库。
