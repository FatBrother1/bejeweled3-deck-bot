# 运行参数说明

参数名、默认值、可选值都是从 `bot/bot_v6.py` 的 argparse（第 377 到 401 行）和
`bot/run2.sh` 里抄的，没有推测；代码里没写的东西这里也不写。日常入口是 run2.sh，
它把常用组合封好了；要自己调参就直接跑
`cd /home/deck && python3 bot_v6.py --mode auto --engine pro --vision mem --still-ms 250`。

## 模式（--mode）
默认 `auto`。可选值是 `auto`、`normal`，加上 modes 注册表里的八个模式标识
`poker` `diamond` `butterfly` `lightning` `icescape` `zen` `quest` `classic`
（argparse 的 choices 就是 `["auto","normal"] + modes.keys()`）。`auto` 先看画面判
是不是牌局（判据是左侧绿色分值表），不是就交给 modes 注册表按棋盘特征认，第一个
认领的赢，没人认领落 `classic` 兜底；`normal` 是点名「普通」、不做画面识别；直接
点名八个模式之一则把 hint 交给注册表、不猜。八个模式的中文名写在各自
`modes/<key>.py` 里：poker 牌局、diamond 钻石矿、butterfly 蝴蝶、lightning 闪电、
icescape 冰风暴、zen 禅意、quest 任务、classic 经典。

## 引擎（--engine）
默认 `pro`，可选 `pro` / `fast`。`pro` 走 `solver_pro.py`，`fast` 走 `solver_fast.py`。
注意代码里那句「`solver_fast.py` 不在发布包里」是早期写的注释，**已经过时**：
这个文件现在在仓库里（`bot/solver_fast.py`），发布包里也有，所以 `--engine fast` 是能用的。
真导入失败时代码会打一行警告并回退 `pro`。

## 视觉后端（--vision）
默认 `auto`，可选 `auto` / `mem` / `vision_np` / `vision_np2`。`auto` 先问
`reader_mem.mem_available()`：可用就用内存，报「不在游戏中」时也先挂内存（停在菜单
本来就读不到棋盘，进游戏后再定），其它原因不可用就退视觉。`mem` 强制内存后端
`MemReader`（像素差判静止 + 内存读棋盘），`vision_np` / `vision_np2` 强制视觉
（`FastReader`）。

## 静止判定（--still-ms）
默认 `250.0` 毫秒，作为 `min_still_ms` 传给 reader，意思是画面连续安静够这么多毫秒
才算「这一帧可以读」。run2.sh 里固定传 250。

## 步数、时长与续局
- `--moves`，整数，默认 `0`，跑满多少步就停，0 表示不限。
- `--max-seconds`，浮点，默认 `0`，跑满多少秒就停，0 表示不限。
- `--auto-restart`，开关，默认关，打开后当局结束自动点「再来一次」。
- `--no-pending`，开关，默认关，打开表示关掉 pending 优化、每步都重新等静止。
- 另有一个不走命令行的开关：文件 `/home/deck/bjbot/autorestart`（内容 1 或 0）。
  run2.sh 读它决定加不加 `--auto-restart`，环境变量 `AUTORESTART` 可单次覆盖。

## 抓帧
`bot_v6.py` 没有抓帧后端的命令行开关，抓帧由 `cap2.Cap` 自己决定：优先 PipeWire
（`capture_pw.PwCapture`，启动时从 `pw-dump` 找 `Video/Source` 节点，节点号不写死），
失败退 `gamescopectl`（约 2fps），在兜底路径上每 60 秒回试一次 PipeWire，回来了自动
切回；两条路都不行会打 `抓帧失败: ...` 并直接退出。跟抓帧沾边的两个参数其实是落盘
用的：`--death-shot DIR` 在检测到游戏结束时把画面连拍到 DIR（用来标定按钮位置）；
`--out 文件` 在跑完时把这一轮统计写成 JSON（engine / vision / still_ms / moves /
seconds / s0 / s1 / ok / per_step / stats / rows）。

## 调试
- `--no-click`：只识别不点击，`run2.sh dry` 用的就是它。
- `--out` 与 `--death-shot` 见上一节。
- bot 自己不打日志文件，日志是守护 `watch2.py` 把 stdout 追加到
  `/home/deck/bjbot/bot.out` 得到的。

## run2.sh 的子命令
| 子命令 | 实际做的事 |
|---|---|
| `on` | 先停 `bejewel-watch` 并清掉残留 bot，再用 `systemd-run --user --unit=bejewel-watch --collect` 起 `watch2.py`；临时单元，重启 Deck 失效 |
| `off` | 停 `bejewel-watch`，再 pkill 掉 bot 与 watch2 |
| `status` | 打印守护、bot、游戏三行状态，外加当前续局开关 |
| `logs [N]` | `tail -n N /home/deck/bjbot/bot.out`，N 默认 30 |
| `modes` | 列 `/home/deck/bot_*.py` 里认得的模式（排除 `bot_v6`），并提示 run 的用法 |
| `run <模式> [步数]` | 模式写 `auto` 就跑 `bot_v6.py --mode auto`，写别的就跑 `bot_<模式>.py`；脚本不存在直接报错退出 |
| `play [N]` | 前台跑 `bot_v6.py`，`--mode auto --engine pro --vision mem --still-ms 250` |
| `turbo [N]` | 与 `play` 命令行完全相同（pending 优化已内置） |
| `dry [N]` | 同 play 但加 `--no-click`，只识别不点击 |
| 无参数/不认识 | 打印脚本头部第 2 到 12 行的帮助 |

代码里确认过的几点：默认步数 `play`/`turbo`/`run` 是 0（不限）、`dry` 是 3；这四个
子命令都会带上 `$RSFLAG`，也就是续局开关打开时补 `--auto-restart`；`on`/`off` 里用
`pkill -f "python3 /home/deck/bo[t]_"`（方括号是为了让 pkill 不匹配到自己的命令行，
这条坑项目里踩过）；脚本开头会 export PATH、XDG_RUNTIME_DIR、DBUS_SESSION_BUS_ADDRESS
并 `cd /home/deck`，所以在任何目录下调用都行。
