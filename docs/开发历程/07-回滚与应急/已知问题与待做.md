## ~~P1 · 牌局模式：手牌结算覆盖层会挡住输入~~（2026-09-27 已修，上机验证通过）

打出手牌后，画面中央会弹一层结算覆盖层（五张牌 + 牌型名 + 加分），它会**吃掉鼠标输入**。

- **已修**：`modes/poker.py` 新增判据（区域 `(570,330)-(1010,470)` 白像素占比 > 0.15），
  经 `modes/base.py` 的 `overlay_action` 钩子由引擎每步开头调用，认出后清拉黑、
  轮询等它放完（最多 8 秒），这一步不出手也不计死局。
- 判据实测三张真实帧：覆盖层 **0.475** / 正常对局 **0.004** / 游戏结束画面 **0.000**，
  阈值 0.15 两侧余量都在 3 倍以上。
- 上面「趴窝大约 80 秒」是**后果**、不是覆盖层本身的时长 —— 覆盖层实测约 **2 秒**，
  80 秒是它引发的「拉黑 → 掩码 → 无走法风暴」那一串。
- 详见 `02-技术报告/28-牌局风暴根因与牌色修正-20260927.md`。

## ~~P1 · 牌局模式：连续找不到走法会退出重启~~（2026-09-27 已修，上机验证通过）

牌局偶尔会进入「无走法风暴」，日志刷 `牌局无走法(N)等洗牌...`，然后 1~3 分钟
退出一次、由守护重新拉起。

- **已修**：根因是三个环节叠加 —— ①结算覆盖层那 2 秒不接受交换
  ②牌局求解器 `rank_moves_poker` 没有 `banned` 参数，被拒的同一招每一步都被重选
  （实测同一招连拒 3 次）③掩码把本来只有 3 招的盘掩成 0 招。
  改法 = 认覆盖层 + 过滤走法级拉黑 + 弃用掩码盘（直接用 `g_raw`）。
- 上面「覆盖层挡着的时候棋盘是冻的」说反了：风暴中内存盘实测**有 3 招**、
  游戏时钟在走（2 秒涨 199 厘秒），是掩码把它掩成了 0 招。
- 详见 `02-技术报告/28-牌局风暴根因与牌色修正-20260927.md`。

## P2 · 牌局：覆盖层放完那一下仍会被拒

上机实测（2026-09-27 22:10 部署后 9 分钟）：认出结算覆盖层 43 次，
剩下的拒绝里有 **38% 发生在覆盖层放完 3 秒内**（例：22:10:31 认出覆盖层、
22:10:34 那一步仍被拒）。

- 说明**游戏锁输入的时长比可见的覆盖层长**，认出覆盖层只解决了「明知故犯」，
  还没解决「放完就出手」。
- 影响很小：这类拒绝每次只废掉一步，而且走法级拉黑已经保证不会重试同一招。
- 要做的话：覆盖层消失后再多等一拍（或等手牌面板复位）再出手。

## P2 · 结算判据会在「过关过场动画」上误命中

逐帧探针跑过 68790 帧：正常对局最高 0.458，过关那一下橙色旋涡过场能到 0.943~0.954，
超过 0.75 的阈值，于是 bot 会在过关瞬间点一次「再来一次」并清空拉黑表。

- 实测无害（点完照常进下一关），所以没动。
- 阈值 0.75 在正常对局里没有误报。
